# Vue 3 전환 및 UI/UX Pro Max 적용

## 실행

- `npm ci` 후 `npm start`. 기존 `.env.loc` / `.env.loc.local` 설정을 사용합니다.
- 고객 앱은 9000, 관리자 앱은 9100 포트입니다. API를 함께 확인하려면 백엔드에서 `python3 scripts/run-local.py`를 실행합니다. 백엔드 종료 시 RabbitMQ도 함께 종료됩니다.
- `npm run build` 또는 `npm run build:prd`는 운영 모드, `npm run build:loc`는 로컬 모드 빌드입니다. 운영 빌드는 macOS/Linux 셸에서 `NODE_ENV=production`을 명시합니다. 관리자 운영 경로는 `/admin/`이며 `VUE_APP_PUBLIC_PATH`로 재정의할 수 있습니다.

## 변경 내용

- Vue 3.5 / Vue Router 4 / Vuex 4. Vue CLI 5와 Options API를 유지합니다. `createApp`, `createRouter`/`createWebHistory`, `createStore`를 사용합니다.
- `vue-template-compiler`를 제거하고 Vue와 버전이 일치하는 `@vue/compiler-sfc`를 사용합니다. ESLint와 Vue 플러그인도 서로 호환되는 버전으로 정리했습니다.
- Vue 3의 마운트 방식에 맞춰 App 내부 중복 `id=app`을 없앴습니다. 종료 훅은 `beforeUnmount` / `unmounted`로 전환했습니다.
- 라우트의 catch-all 문법, 해시 스크롤 옵션, 반복 템플릿 key를 Vue 3에 맞췄습니다. 인증 정책과 API 계약은 유지합니다.
- UI/UX Pro Max는 루트 `.codex/skills/ui-ux-pro-max`에 설치했습니다. 저장소 AGENTS 규칙을 통해 UI 작업 시 탐색합니다.
- `design-system/`의 MASTER.md와 `src/assets/scss/theme.scss`가 디자인 기준입니다. 기존 아웃도어 색상을 유지하고 글자 크기, 초점 표시, 모바일 입력, reduced-motion, 공통 패널을 정리했습니다.

## 로컬 검증 (2026-10-25)

- 두 앱의 운영/로컬 빌드와 실제 브라우저 구동을 확인했습니다.
- 375 / 768 / 1024 / 1440px에서 주요 레이아웃을 확인했습니다. 관리자 모바일 상세의 가로 넘침을 수정했습니다.
- 실제 API로 고객 상품 목록·상세·이벤트, 비로그인 문의 접근 시 로그인 이동, 잘못된 로그인 오류, 회원가입 화면을 확인했습니다.
- 임시 로컬 관리자 정상 로그인, 상품 검색·빈 결과·초기화·페이지 이동, 상품 상세·등록 폼 옵션, 이벤트·회원·관리자·문의 메뉴, 로그아웃을 확인했습니다. 임시 계정·로그인 기록·자격증명 파일은 삭제했습니다.
- 고객 로그인 성공, 회원정보 저장, 상품/이벤트/회원 변경 저장은 이번 브라우저 검증에 포함하지 않았습니다. 운영 환경에는 반영하지 않았습니다.
- 고객 앱 전체 린트에는 기존 탭/공백, 사용하지 않는 변수, 오류 처리 등 860개 오류와 2개 경고가 남아 있습니다. 같은 Vue 3 규칙으로 기존 HEAD와 비교하면 기존 910개 오류에서 감소했고 새 규칙 위반은 없습니다. 무관한 일괄 포맷이나 인증 로직 수정은 하지 않았습니다.
- 고객 빌드에는 기존 로그인 배경 PNG(259 KiB)의 asset-size 경고가 있습니다. 빌드는 성공합니다.

## 코드 리뷰 후 보완

- 고객 문의 페이지 수를 비동기 응답 후 계산하고, 고객·상담원 모두 정수배에서 빈 페이지가 생기지 않도록 수정했습니다.
- 관리자 상품 목록·상세는 할인가 0원을 유지하고 null/undefined일 때만 판매가를 사용합니다.
- 관리자 상품·문의·회원·관리자·이벤트 목록은 요청 번호로 마지막 조회만 반영합니다. 이전 응답의 성공/실패/로딩 종료가 최신 상태를 바꾸지 않으며, 잘못된 날짜로 재조회해도 이전 요청은 반영하지 않습니다.
- `npm run test:regression`으로 실제 컴포넌트 메서드를 대상으로 응답 순서·실패·가격·페이지 경계를 검증합니다. Node 기본 테스트 러너를 사용하며 추가 테스트 라이브러리는 없습니다. 고객 3개, 관리자 22개 테스트가 있습니다.
- Docker 빌더는 Node 22를 사용하고 `npm run build:prd`를 실행합니다. `.env*`는 이미지 복사에서 제외하므로 환경별 값은 기존 Docker build ARG로 전달합니다.

## 예외 처리 보완 (2026-10-26)

- 고객 요청 인터셉터에서 반환하지 않던 rejection과 도달할 수 없는 코드를 수정했습니다. HTTP 오류·네트워크 오류·타임아웃은 정상 응답으로 바꾸지 않고 원래 오류로 전달합니다.
- 공통 요청을 사용하는 고객 문의 조회·등록·수정과 상담원 조회·담당자 지정·답변·로그아웃 화면의 누락된 catch를 보완했습니다. 문의 수정의 잘못된 두 번째 then을 catch로 변경했고, 상담원 조회 실패 시 새로고침 표시와 타이머도 함께 정지합니다.
- 상담원 로그아웃은 오류 원인 없이 reject하거나 빈 응답을 다시 참조하지 않습니다. 관리자 로그아웃 실패는 사용자에게 알리고 기존 로그인 정리·이동 정책을 유지합니다.
- 빌드 설정 파일의 Node 환경과 번들에 주입되는 process 전역을 ESLint에 명시했습니다. 규칙을 끄지는 않았습니다.
- 회귀 테스트: 고객 21개, 관리자 26개 통과. 두 앱 운영 빌드와 관리자 린트 통과. 고객 린트는 탭·공백 858개, 컴포넌트 이름 2개와 기존 shorthand 경고 2개가 남아 있으며, 이번에 확인한 예외 누락·도달 불가·사용하지 않는 변수 오류는 제거했습니다.

## 형식 오류 정리 (2026-10-26, 최종 상태)

- 오류가 있던 고객/상담원 문의 화면 등 6개 파일의 탭을 공백으로 바꾸고 2칸 들여쓰기·줄 끝 공백을 정리했습니다.
- 상담원 로그인은 `CsrLoginView`, 404 화면은 `NotFoundView`로 컴포넌트 이름을 명시했습니다. 라우트·파일 경로는 유지합니다.
- 두 객체 속성에 shorthand 문법을 적용해 경고도 없앴습니다. 린트 규칙은 완화하지 않았습니다.
- 두 앱 `npm run lint -- --no-fix` 통과(오류·경고 0). 고객 회귀 테스트 21개, 고객 운영 빌드 통과. 기존 배경 이미지 크기 경고는 빌드에 남아 있습니다.
- 변경 전후 AST와 컴파일된 render 코드를 비교해 컴포넌트 이름 외의 로직·화면 출력이 같음을 확인했습니다. 스타일과 기존 주석도 유지했습니다. 이전 절에 기록된 잔여 린트 오류는 이 정리로 해소되었습니다.
